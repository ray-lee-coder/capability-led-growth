# CLG 研究与迭代方法

CLG 不是等待一次实验宣判的命题，而是一套正在形成的营销模型。

AI 让能力可以被包装、分发和调用，但这并没有自动回答企业应该怎样利用它建立市场关系。
当前阶段的任务，是把观察变成概念，把概念变成设计，再让真实结果反过来修改概念。

```text
观察新现象
→ 提出工作概念
→ 设计一次 CLG 实践
→ 进入真实场景
→ 记录行为、结果与成本
→ 比较、反证和解释
→ 修改模型与下一轮设计
```

这个循环允许模型不完美，也允许某些判断最终被推翻。反证的意义不是尽快结束研究，而是
防止任何结果都被解释成模型正确。

## 当前要逐步回答的问题

1. 哪些能力适合成为用户与企业建立关系的第一触点？
2. 能力进入用户已有环境后，如何被发现、理解、信任和再次使用？
3. 价值怎样自然归属于提供方，而不污染任务结果？
4. 一次能力使用怎样延续为注册、留资、销售机会、付费或长期关系？
5. 哪些机制跨行业和载体有效，哪些只属于特定 Skill、运行时或场景？
6. 能力分发相较内容、免费工具和产品试用，带来了什么不同？

这些问题不会由一轮实验统一回答。它们需要产品设计、案例比较、对照实验、失败样本和长期
运营数据共同推进。

## 每次实践应该留下什么

一次 CLG 实践不只记录转化率。它至少应该留下五类认识：

| 层面 | 需要记录的问题 |
|---|---|
| 能力 | 用户是否很快获得有意义的结果，能力边界是否合适 |
| 分发 | 用户从哪里发现能力，它是否进入了原本触达不到的环境 |
| 关系 | 用户是否理解来源、建立信任并愿意继续互动 |
| 增长 | 是否产生复用、分享、注册、留资、销售机会或付费 |
| 代价 | 推理、审核、支持、适配、平台抽成和人工介入成本 |

结果需要明确修改模型的哪一部分。没有增量，可能说明能力切片太轻、分发渠道不对、价值
没有归属于提供方，或下一步承接与任务脱节。不能简单增加更多 Hook，也不能把失败样本从
CLG 定义中排除。

## 第一项实践：企业 AI 场景分析 Skill

当前项目从企业 AI 场景分析 Skill 开始，因为它已经能够在一次任务中交付完整结果，也与
后续咨询和产品服务保持连续性。

第一轮可以同时承担产品探索和对照研究：

- **供应商入口版**：能力只能在提供方入口使用；
- **可分发版**：任务、输出和交付价值尽量一致，但能力进入用户已有环境；
- **共同记录**：首次有效任务、结果采用、30 天与 90 天复用、分享、注册、留资、销售机会、
  付费、质量与总成本；
- **定性研究**：用户为何调用、是否理解来源、为什么愿意或不愿意继续关系。

对照实验帮助识别分发形态的增量，但不会独自定义 CLG。即使两组没有明显差异，用户行为和
访谈仍可能揭示模型缺少的设计环节。

## 反证怎样帮助模型发展

研究需要主动寻找会削弱当前解释的结果：

- CLG 与普通免费工具长期没有稳定差异；
- 能力提供方无法在第三方环境中保留关系；
- 跨运行时适配成本接近重新开发；
- 能力只能作为整体组合被评估，无法形成稳定边界；
- 验证标记无法预测真实任务表现；
- 可移植能力包主要降低模型迁移成本，反而削弱发布方壁垒。

这些结果不会自动终止项目。它们首先要求修改模型：缩小适用范围、改变能力边界、重做关系
设计，或承认某些机制属于 PLG、免费工具营销和平台分发。只有连续多轮实践都找不到独特的
解释力或设计价值时，才应该放弃 CLG 这个独立框架。

## 当前探索路线

1. 用企业 AI 场景分析 Skill 建立第一套完整 CLG 设计；
2. 让供应商入口版与可分发版进入真实使用；
3. 建立能力、分发、关系、增长和成本的共同记录；
4. 用数据、访谈、失败样本和对照实验修改设计；
5. 比较更多能力与行业，寻找重复出现的机制；
6. 再决定哪些部分值得抽象为能力运营与营销注入工具。

这项研究的产物不只是一个最终结论，也包括逐步清晰的概念、设计原则、失败模式、测量方法
和产品工具。它们共同回答一个仍然开放的问题：在 AI 能力可以独立流通的时代，营销应该
怎样重新设计？
