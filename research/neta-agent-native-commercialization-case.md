# Neta：从 Skill 分发到 Agent-native 商业闭环

研究日期：2026-06-13

## 总体判断

Neta 是当前 CLG 研究中最重要的对照案例之一。它不只是用开源 Skill 为产品获客，也不只是
把 API 包装成 CLI。它正在把产品的一部分发现、使用、身份、状态、计量、社区和交易能力，
外化到用户的 Agent 环境中。

> Neta Skills 是一个仍在演进中的外部产品面。Skill 负责意图与工作流，CLI 负责执行和系统
> 连接，Neta 服务负责价值、状态、社区和商业化。

公开材料可以证明这套结构已经存在，但不能证明它已经获得稳定收入、留存或渠道增量。

## 一条被压缩的商业路径

```text
在 Skill 目录、GitHub 或 Agent 中发现能力
→ Agent 根据意图选择聚焦 Skill
→ CLI 调用 Neta API 完成创作
→ OAuth 登录建立账户关系
→ AP、作品和角色形成持续状态
→ 配额或更高需求出现时查看套餐并创建订单
→ 浏览器完成 Stripe Checkout
→ CLI 再次验证套餐并继续任务
```

支付并没有完全发生在 CLI 中。CLI 负责套餐发现、订单创建、支付会话发起和结果验证，最终
支付仍交给浏览器与 Stripe。这保留了明确的人类确认边界。

## 产品结构拆解

| 层级 | Neta 的实现 | 产品作用 |
|---|---|---|
| 发现与安装 | GitHub、`skills add`、npm、第三方目录 | 把能力带到用户环境 |
| 意图与路由 | `neta` 路由 Skill，多个聚焦子 Skill | 让 Agent 选择正确能力 |
| 工作流知识 | Skill 指令与 references | 教 Agent 组合命令完成复杂任务 |
| 执行适配 | `@talesofai/neta-skills` CLI | 将 Agent 意图转成稳定 API 调用 |
| 价值交付 | 图片、视频、歌曲、角色、Elementum、Adventure | 完成真实创作任务 |
| 身份关系 | Token 与 OAuth Device Flow | 将使用连接到账户 |
| 状态与资产 | AP、Artifacts、Characters、Collections、Campaigns | 支持继续、复用和留存 |
| 社区与发现 | Feed、标签、推荐、关注、点赞、评论、发布 | 形成内容和关系循环 |
| 计量与运营 | 命令、参数、结果、耗时、版本、地区、用户 UUID | 观察使用并改进能力 |
| 商业化 | 套餐、订单、Stripe Checkout、套餐验证 | 在任务环境中承接付费 |

将 Neta 简化为“Skill 获客”会低估它的产品设计。

## CLI 为什么关键

Skill 可以告诉 Agent 何时以及如何使用一项能力，但真实生成、账户访问、订单创建和状态读取
仍需要稳定执行层。CLI 将这些操作封装为 Agent 可以调用的明确命令，并通过 API 连接后端。

Neta CLI 不只包含生成命令，还包含登录、用户信息、AP 余额与历史、作品和角色管理、社区
互动，以及套餐、订单和支付。因此它不是窄义开发者工具，而是无图形界面的产品客户端。

公开代码还显示，登录用户执行命令时，CLI 会记录命令、结果、耗时、版本、地区与参数，为
能力级运营提供基础。但当前实现会把字符串、数字、布尔值和数组参数加入事件，可能包含
提示词、文件地址或其他任务信息。即使可以通过 `DISABLE_TELEMETRY=1` 关闭，这仍提示 CLG
系统应默认区分运营元数据和用户任务内容。

## 获客、激活与留存

Neta 使用两条分发轨道：

```text
Skill 分发意图与工作流
CLI / npm 分发执行能力
```

开源仓库同时承担信任、文档、搜索发现和社区传播。Skill 被安装进 Agent 后，入口可能在后续
相关意图中再次出现，而不只是一次网站访问。

它的激活优势是用户可以直接提出创作任务，Agent 再读取工作流帮助选择模型、角色和后续步骤。
但 Node 环境、Skill 安装、CLI 调用、认证、网络和额度也会形成摩擦。它更像扩大产品入口，
而不是证明 CLI 会替代所有界面。

真正值得关注的留存结构不是生成命令，而是长期状态：Artifacts、Character、Elementum、
Collections、Adventure Campaigns，以及关注、点赞、收藏、评论和推荐。Skill 负责进入任务，
状态和社区负责让用户留下。

## 商业化：上下文内交易

Neta Creative Skill 明确规定：当创建被额度或频率限制时解释原因；如果升级符合用户目标，
只提供一次升级路径；先查询当前套餐，之后列出套餐、创建订单、发起 Stripe Checkout，并在
支付后再次验证套餐。

这不是套餐页曝光，而是上下文内商业化：

> 交易发生在用户已经表达目标、获得价值或遇到真实约束的时刻。

它还要求 Agent 不要在同一对话中重复推销。Agent 能理解上下文，也可能比传统弹窗更令人
反感，因此商业行为规则本身需要成为 Skill 的一部分。

## 商业引擎拆解

Neta 的商业结构可以分成四层：

| 层级 | 机制 | 作用 |
|---|---|---|
| 免费分发 | 开源 Skill、GitHub、目录与 npm | 降低发现、信任和试用成本 |
| 使用计量 | 每次生成消耗 AP，账户可查看余额和历史 | 把能力使用转成可管理的稀缺资源 |
| 订阅升级 | 套餐、订单、Stripe Checkout、套餐确认 | 在需求清楚时承接付费 |
| 资产与网络 | 角色、元素、作品、活动、社区互动 | 提高复用、留存和潜在再分发 |

AP 已经构成使用计量层，但公开资料不足以证明 AP 充值本身是否是独立收入来源。因此不能把
“存在余额与消耗历史”直接等同于“按量付费模式已经成立”。

官网并未消失。它仍承担适合图形界面与人类确认的工作，例如登录、完整应用体验和 Stripe
Checkout。Neta 的策略不是用 Agent 取代官网，而是把官网从唯一入口变成多个产品面之一。

## 两个可能的增长循环

```text
能力使用循环：
发现 Skill → 完成创作 → 登录并保留资产 → 复用 → 消耗 AP 或升级 → 继续创作

内容社区循环：
创建作品或玩法 → 发布 → 被推荐、搜索或浏览 → 被互动或改编 → 带来新创作任务
```

第二条循环如果成立，会让用户产出成为下一轮获客和激活材料。但目前没有公开数据证明循环
系数、循环周期或商业贡献。

## 从版本演进观察产品意图

| 版本 | 主要变化 | 对商业闭环的意义 |
|---|---|---|
| 0.3 | 发布 Collection | 用户结果进入产品与社区 |
| 0.5 | 推荐、发现和互动 Feed | 建立内容发现循环 |
| 0.9 | 角色创建与管理 | 建立可复用资产 |
| 0.12 | Adventure | 扩展长期、多轮使用 |
| 0.14 | Premium 套餐与订单支付 | 补齐交易 |
| 0.14.2 | 使用分析 | 补齐运营反馈 |
| 0.16 | OAuth Device Flow | 降低账户关系建立摩擦 |
| 0.17 | 用户、AP、历史与作品 | 补齐账户状态与使用管理 |

这不一定是预先规划的路线，但可以看出项目正在从“可调用能力集合”走向“可经营外部产品面”。

## 它验证了什么，又没有验证什么

Neta 验证了 Skill 可以成为获客和分发入口；Skill 可以承载商业规则；CLI 可以成为跨 Agent
的执行、身份、计量和商业适配层；能力使用可以在官网外连接到账户、资产和付费；能力组合
需要路由 Skill 与聚焦子 Skill。

它尚未证明 Skill 安装带来增量用户，Agent 渠道的激活、留存和付费优于 Web 或 App，公开
仓库传播转化为真实使用，社区形成可持续循环，或 CLI 付费链路降低了交易摩擦。

## CEO 审评：最强之处与最大风险

### 最强之处

Neta 没有把 Skill 当作文档或广告，而是让它连接真实产品能力。更关键的是，项目没有停在
首次调用，而是继续补齐账户、状态、资产、计量和交易。这使 Agent 渠道具备独立形成用户
关系和商业结果的可能。

它也避免了一个常见错误：让单体 Skill 无限膨胀。路由 Skill 与聚焦子 Skill 的拆分，使
能力目录本身开始具备产品信息架构。

### 最大风险

1. 安装、Node、认证、额度和浏览器跳转叠加后，真实激活路径可能仍然很长。
2. `npx ...@latest` 提高使用便利，也带来版本漂移和供应链风险。
3. Skill 目录与 Agent 平台可能控制未来的发现、权限和交易规则。
4. 登录用户的命令参数遥测可能收集超出运营所需的任务内容。
5. 49 个命令和多个 Skill 会增加 Agent 路由、文档维护和一致性成本。
6. 公开传播指标不能替代激活、留存、收入和增量证据。

因此，Neta 最值得学习的是完整结构和迭代方向，而不是逐项复制实现。

## 值得持续跟踪的指标

| 环节 | 关键指标 |
|---|---|
| 分发 | Skill 安装、目录来源、CLI 首次调用 |
| 激活 | 安装到首次成功创作率、首次价值时间 |
| 关系 | 首次价值到登录率、资产保存率、复用率 |
| 内容循环 | 发布率、被发现率、改编率、再分发系数 |
| 商业化 | 额度触发率、套餐查询率、订单创建率、支付完成率 |
| 增量 | Agent 渠道与其他渠道的对照结果 |
| 经济性 | 单次有效创作成本、付费用户回收期 |
| 护栏 | 遥测退出率、隐私投诉、失败率、重复推销率 |

## 对当前产品的直接启发

企业 AI 场景分析 Skill 不需要照搬创作产品的社区结构或立即加入支付，但应该认真研究 CLI
作为执行适配层的价值：

```text
企业分析 Skill
→ 分析 CLI / 服务
→ 报告与任务历史
→ 用户主动连接和同意
→ 继续分析、分享、团队协作
→ 深度分析或咨询服务
→ 指标与生命周期反馈
```

最值得借鉴的不是某个命令，而是 Neta 将增长、产品和商业化连接到同一次能力使用中。
