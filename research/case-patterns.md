# 相邻案例谱系：能力如何逐步成为增长入口

没有一个现成案例完整证明 CLG，但相邻产品已经分别展示了它所需要的组成部分。把这些案例
放在一起，比寻找一个完全同类的竞争产品更有用。

## 案例总览

| 案例 | 已经发生的变化 | 对 CLG 的启发 | 仍缺少什么 |
|---|---|---|---|
| HubSpot Website Grader | 免费工具用真实结果代替内容说服，并可嵌入合作伙伴网站 | 可执行能力可以成为获客入口 | 能力仍主要由网站承载 |
| Grammarly | 写作能力进入大量第三方应用和网站，在用户工作处持续交付价值 | 产品能力可以离开主产品入口 | 能力仍与完整产品和账号紧密绑定 |
| Calendly | 用户把调度能力通过链接送给下一位参与者 | 一次使用可以同时完成价值交付与分发 | 分发的是交互入口，不是独立能力包 |
| Canva Templates / Creators | 模板让创作者能力和产品使用一起被分发 | 可复用资产可以形成供给、发现和再创作循环 | 模板主要承载创作起点，不直接执行复杂任务 |
| ChatGPT Apps | 应用在对话意图出现时被推荐和调用，开发者触达用户无需先把用户带回网站 | 能力可以在用户的 Agent 环境中被发现和使用 | 平台控制推荐、连接、数据和商业规则 |
| Agent Skills | 流程知识、脚本和资源成为可移植、可版本控制的能力包 | Skill 是研究 CLG 的现实载体 | 规范不负责增长归因与关系承接 |
| NVIDIA Verified Skills | 能力被编目、扫描、签名、记录来源并附 Skill Card | 能力规模化后需要治理与生命周期管理 | 验证不等于用户价值或增长效果 |

## 1. HubSpot Website Grader：可执行内容的前身

Website Grader 让用户提交网站并获得性能、移动端、SEO 和安全评分。HubSpot 将其称为免费
网站审计工具；其案例页面还说明，这个工具既运行在 HubSpot 平台，也可以由 HubSpot 合作
伙伴部署在自己的网站。

它展示了一个长期有效的营销原则：与其发布一篇“如何改善网站”的文章，不如直接替用户
检查网站。能力交付和需求教育发生在同一次任务中。

它与 CLG 的差别在于，能力仍主要由网页承载。Skill 让同类能力有机会进一步进入 Agent 和
用户工作环境。

来源：[Website Grader](https://website.grader.com/)、[HubSpot 案例](https://inspire.hubspot.com/hubspot-website-grader-expertise-with-a-click-of-a-mouse)

## 2. Grammarly：能力跟着用户走

Grammarly 的官方页面强调，其能力可以在超过一百万个应用和网站中工作。用户不必每次返回
Grammarly 编辑器，写作辅助会出现在邮件、文档、Slack 和其他工作环境里。

这证明“产品进入用户工作流”并不是 Agent 时代才出现的现象。区别在于，浏览器扩展仍是
一套由厂商控制的产品分发；开放 Skill 则可能被复制、修改、组合并由不同运行时调用。

来源：[Where Grammarly Works](https://www.grammarly.com/where-grammarly-works)

## 3. Calendly：使用即分发

Calendly 用户把调度链接放进邮件或 LinkedIn 消息，接收者无需先理解产品，就可以直接完成
预约。官方材料也强调，潜在客户可以不离开收件箱完成预约。

这是经典 PLG 增长循环：一个用户使用产品时，下一位用户自然接触到产品能力。CLG 希望把
这种循环从协作链接扩展到更多可执行能力。

来源：[Calendly sales tips](https://calendly.com/blog/pro-tips-for-sales)

## 4. Canva：可复用资产形成供给循环

Canva 允许用户通过模板链接分享设计，也通过 Creators 计划让创作者向大量用户分发模板、
元素和教育内容并获得收益。

Canva 展示了另一种生命周期：资产被创建、审核、发现、复用、修改和再次分发。能力单元
未来也可能形成类似循环，但它比模板多出运行质量、权限、成本和结果责任等问题。

来源：[Canva Templates](https://www.canva.com/templates/)、[Canva Creators](https://www.canva.com/creators/)

## 5. ChatGPT Apps：能力在意图出现时被发现

OpenAI 的官方介绍写得很直接：应用可以在 ChatGPT 对话中被用户点名，也可以在相关语境中
被建议；开发者因此能够在用户最需要它的时候触达用户。应用目录和深链则提供了额外发现
入口。

这是 CLG 最关键的基础变化之一。分发不再只依赖用户搜索品牌或访问网站，Agent 可以根据
当前任务发现并调用能力。

风险同样明确：平台掌握推荐、审核、连接和数据规则。能力提供方必须经营平台关系，也要
避免把全部用户关系交给单一运行时。

来源：[Introducing apps in ChatGPT](https://openai.com/index/introducing-apps-in-chatgpt/)、[App Directory submission](https://developers.openai.com/apps-sdk/deploy/submission)

## 6. Agent Skills 与 NVIDIA：能力生命周期开始显性化

Agent Skills 规范把指令、脚本、参考资料和资源组织成可移植、可版本控制的文件夹。官方
评测指南进一步要求使用真实测试任务、期望结果和结构化评测反复改进 Skill。

NVIDIA Verified Skills 又向前走了一步：能力被编目、扫描、签名、记录来源，并用 Skill
Card 描述。这些动作已经接近能力单元生命周期管理，只是重点仍在质量、来源和治理，而不是
营销关系。

来源：[Agent Skills Overview](https://agentskills.io/home)、[Evaluating Skills](https://agentskills.io/skill-creation/evaluating-skills)、[NVIDIA Verified Agent Skills](https://developer.nvidia.com/blog/nvidia-verified-agent-skills-provide-capability-governance-for-ai-agents/)

## 从案例中得到的判断

相邻案例已经分别证明了五件事：

1. 真实任务可以承担获客和教育；
2. 产品能力可以进入用户工作的地方；
3. 一次使用可以同时成为下一次分发；
4. 可复用资产需要发现、治理和持续运营；
5. Agent 平台可以在意图出现时匹配能力。

CLG 把这些已经出现的机制组织成一套 PLG 运营模型：企业如何选择能力、分发能力、保留
关系、承接需求，并持续管理能力单元的生命周期。接下来的案例研究负责把这套模型的边界和
做法逐步补全。
